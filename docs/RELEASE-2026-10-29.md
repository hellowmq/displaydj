# Full 1.1.0 / Lite 0.2.0 发布验证

本批次分别使用新标签 `v1.1.0` 和 `lite-v0.2.0`，Full 为稳定版，Lite 保持预发布，不覆盖或移动已有版本标签。两款产品包含同一共享内核的 DDC 校验修复、诊断导出与生命周期/连接恢复协调改进。

## 验证范围

| 项目 | 结果与边界 |
| --- | --- |
| 自动测试 | 773 项通过：XCTest 187 + Swift Testing 586；包括多进程锁、恢复责任、过期请求、诊断脱敏和真实 DDC 回复帧回归 |
| H27T22S 硬件亮度 | Apple M1 / macOS 27.2 / DP→DP；修复前回复无效，修复后原生查询连续返回完整、校验正确的 0/100。Release CLI 完成 0%→3%→0% |
| 已安装 Full 界面 | 使用安装路径内的修复二进制，经界面完成 0%→5%→0%，独立 DDC 进程分别回读 5% 和 0% |
| 已安装 Lite 界面 | 同一稳定目标，经界面及方向键完成 0%→5%→0%，独立 DDC 进程确认；恢复后状态就绪 |
| 默认数据目录与升级 | 两版安装文件匹配验证候选；实际加载路径、SHA-256 与 inode 核对一致；原恢复记录保留。App 退出后替换，未清空配置或重置权限 |
| 当前连接内核的实体检查 | Dell 下两版普通断开/恢复、物理拔插刷新通过；Lite 主界面异常终止后约 5 秒恢复上线，稍后记录收尾。该次同时存在应用作用域与保护子进程，未单独归因于其中一个机制 |
| 唤醒 | 仅覆盖短时 DarkWake/FullWake 后状态正常；未以约 2 秒循环冒充长时间待机或全部休眠场景 |
| 诊断 | Full/Lite 均经原生入口导出真实 JSON/TXT，默认脱敏检查通过，外屏失败状态未伪装成功 |

各层证据分别保留：源码与自动测试、已安装实例操作、固定提交的独立构建、ZIP/DMG 校验、CI 与发布后下载回读。GUI 调节验证所用候选包含相同功能代码，正式包另有新版本号及固定提交标识；不能将两者二进制指纹混用。

## 兼容性与已知限制

- 当前发行仅 arm64，macOS 13 是部署目标，实际硬件验证系统为 macOS 27.2；未新增 Intel、最低系统实机或全型号支持承诺。
- Dell D2720DS 的两条 Mac DP→HDMI 链路仍在 IOAV 查询阶段失败；Windows/DP 转交报告显示可读 63/100。H27T22S 成功不证明 Dell 的故障原因或其 HDMI 路径已修复。
- 曾在自定义 Documents 测试状态目录出现 Full 亮度锁的系统 `open()` 等待；默认目录的安装及本次界面写入通过。原因尚未确定，遇到同类情况应保留恢复依据并检查默认数据目录，不能删除恢复文件冒充成功。
- Mac mini 双外屏、长时间休眠、镜像/身份变化的完整实机矩阵、真正同时竞争的实体事务、旧保护进程与新意图竞争，以及干净首装均未由当前设备完整验证；相关逻辑有自动测试覆盖。
- 新协调协议仅适用于参与协议的新版本、同一用户与默认临时目录；不扩展为旧版本混跑保证。Full 与 Lite 保持独立恢复记录。
- App 为 ad-hoc 签名、未公证，不能当作 Developer ID/Gatekeeper 信任验收。全局键盘控制的权限与物理按键路径不由 DDC 亮度成功代替。

用户已确认以两款安装实例的实际外屏调节和恢复通过作为本轮发布条件；该条件已满足，未追加其他硬件排查。升级前恢复外屏、退出原产品，保留原包及恢复记录。出现回归可回到之前对应产品的 Release，旧版本标签和资产保持不变。
