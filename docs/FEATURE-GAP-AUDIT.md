# 显示功能差距与内建屏验收（2026-09-22）

范围：当前 `master` 工作区，HEAD `35d088d`，含尚未提交的本轮改动；不代表已发布的 0.3.0 安装包。功能判断来自当前代码与官方说明，不用竞品宣传代替本项目实测。

BetterDisplay 是独立应用，分免费版与 Pro，并非 MonitorControl 的付费版本。其开发者也参与 MonitorControl。官方功能比较：https://github.com/waydabber/BetterDisplay/wiki/List-of-free-and-Pro-features 。功能可用性受 Mac、macOS、显示器及连接方式影响。

## MonitorControl：日常体验仍有的差距

官方功能说明：https://github.com/MonitorControl/MonitorControl#major-features 。

| 功能 | DisplayDJ 当前工作区 | 只用内建屏能做什么 |
| --- | --- | --- |
| 内建背光、外屏 DDC 亮度/音量/对比度 | 内建背光与 Gamma 已有；HP 当前连接通过亮度和对比度 DDC 回读与恢复，音量不支持 | 内建背光小幅写入、独立回读、恢复；Gamma 驻留与退出恢复 |
| 自定义快捷键 | 固定亮度快捷键可选启用，需辅助功能授权；可选「已选中」或「鼠标所在」目标，键位仍不可配置 | 已做目标解析与权限路径测试；还需要 App UI 可操作证据 |
| 原生亮度/媒体键、系统 OSD | 未见完整对应实现 | 可用内建屏开发与验证按键、OSD、权限降级；实际外屏映射留待设备 |
| 内建屏到外屏的同步、单滑块控制全部屏幕 | 已加入默认关闭的相同百分点硬件亮度群控；没有持续跟随内建屏环境光变化 | 已做群控计划与失败路径模拟；跨屏实际效果和逐屏错误展示仍需界面验收 |
| 硬件和软件连续混合调光、全黑、虚拟屏遮罩 | 本轮加入显式 Gamma，但没有混合曲线、全黑或遮罩路径 | 可做内建屏 Gamma 上下限、退出/睡眠唤醒及颜色影响验收；混合 DDC 需外屏 |
| 平滑亮度过渡 | 核心有 ramp；不能由此断言全部 GUI 路径均平滑 | 内建屏可观察 GUI 调节与恢复过程 |

MonitorControl 的辅助功能权限主要与原生 Apple 亮度/媒体键有关；本项目显式 Gamma 命令无需该权限，快捷键则另算。以上区分见各自实现与官方 README。

软件调光交互已对照 MonitorControl 的 [菜单滑块处理](https://github.com/MonitorControl/MonitorControl/blob/5ce1a252ad1bde8248d8e4bb69645b28ca4da3e5/MonitorControl/Support/SliderHandler.swift#L311-L342) 与 [亮度／Gamma 路径](https://github.com/MonitorControl/MonitorControl/blob/5ce1a252ad1bde8248d8e4bb69645b28ca4da3e5/MonitorControl/Model/OtherDisplay.swift#L328-L365)：其滑块变化会直接交给亮度控制，软件调光可作为该路径的一部分；没有要求用户在菜单里逐次点击“读取”“应用”。DisplayDJ 现保留用户主动启用、逐屏独立 Gamma 的产品边界，同时让窗口打开／切屏自动读取、松开滑块提交并在失败后重新读取。此处仍不是 MonitorControl 的硬件与软件连续混合曲线。

## BetterDisplay：新增范围按产品价值分层

| 范围 | 官方功能举例 | DisplayDJ 当前差距 / 建议 |
| --- | --- | --- |
| 基础控制，免费功能 | Intel 和部分 HDMI DDC、输入切换、电源、能力检测、CEC、软件遮罩、软件对比度 | 我们仅有 Apple Silicon 的部分 DDC 连续控制；这些依赖对应硬件，先列为后续设备阶段，不把缺设备当成代码通过 |
| 内建屏可推进，免费功能 | 模式/刷新率选择、颜色配置选择、诊断报告、环境光读数、快捷指令集成 | 模式枚举/设置已有；App 已加入独立进程的 15 秒确认与超时回退，尚缺实际界面和崩溃恢复验收。颜色配置、环境光与 App Intents 尚无完整产品路径；先按用户需求选做，不作为 1.0 同等功能门槛 |
| 高级显示，免费或 Pro | 自定义缩放、虚拟屏、灵活 HiDPI、EDID 导出/覆写、HDR/XDR 亮度提升、色彩滤镜与 3D LUT、画中画/串流、布局保护 | 均为独立的大范围功能；部分能在内建屏研究，但需要兼容矩阵和视觉质量验收。不要为了追齐竞品把它们并入近期 1.0 |

BetterDisplay 的免费与 Pro 边界以及硬件限制以其官方比较表为准；其集成 CLI/HTTP 的存在不意味着我们的每项显示功能都已覆盖。

## 本机验证与发布判断

内建屏已验证原生背光约 68.9% → 70.9% → 68.9%，独立读数匹配；亮度预设将约 70.9% 恢复到保存的 68.9%；8 个内建屏模式枚举与当前模式预演；Gamma 100% → 97%，停止并重启隔离服务后恢复 100%；无 Bearer 令牌访问软件调光接口返回 401。HP D27k 当前连接已独立通过 DDC 亮度 56% → 53% → 56%、对比度 80% → 77% → 80% 的写入、回读和恢复；VCP 音量明确不支持。HP Gamma 调到 97% 时独立 CoreGraphics 公式读到 RGB 0.97，硬件亮度维持 56%。写入使用隔离 `DISPLAYDJ_HOME`，私有日志保存在本机临时目录。完整 `swift test` 当前通过 623 项，CLI smoke 通过。命令回读不等于肉眼效果，GUI 视觉验收仍未完成。

下一步需完成工作区 App 实际窗口与交互，尤其是模式确认倒计时、多屏同步及软件调光状态；快捷键权限授予/撤销；真实睡眠唤醒后的 Gamma 视觉状态；首次安装、升级、签名与公证流程。唤醒重应用代码与模拟测试已补；内建屏临时预览的退出恢复、正式设置与手动恢复均已实测。独立模式守护进程在 HP 的真实 WindowServer 上通过确认保留、管道关闭、超时和控制进程异常退出模拟；App 设置窗口本体及其倒计时仍未视觉验收。此前 Dell 当前连接的 DDC 三项只读预检全部在 Get VCP 请求阶段失败，没有硬件写入证据，待同机同屏更换链路对照。详见 [DEVICE-VALIDATION.md](DEVICE-VALIDATION.md)。发布 1.0 的门槛应是承诺的功能稳定、恢复可靠、分发可信及支持范围明确，不是复制 BetterDisplay Pro 功能总数。当前证据仍不足以宣布 1.0。
