# Lite 恢复、覆盖安装与卸载

适用于 Lite 0.1.0 首发候选。完整版/CLI 的会话行为不变。

## 退出前恢复

Lite 正常退出前重新读取自己的记录，逐台恢复并核验。当前可恢复目标全部确认后才退出；记录不可读或当前目标恢复失败时，取消退出，保留记录、错误和重试入口。已取消“保留断开直接退出”。无待恢复记录则正常退出。

有当前待恢复记录时，先完成恢复再断开另一台；Lite 0.1.0 不允许叠加新的断开状态。它不会对网络上发现的屏幕或所有新插入屏幕批量执行“启用”。

## 异常结束时的恢复保护

旧原型沿用 `CGCompleteDisplayConfiguration(..., .forSession)`，断开可超过 App 生命周期。现在 Lite 的**新断开**请求 `.forAppOnly` 应用作用域，但私有连接变更在本机实测没有随主进程结束回退，因此不能以此单独承诺恢复。重新连接使用 `.forSession`，以清除旧原型可能留下的会话断开基线。代码不会使用 `.permanently`，Lite 也不写显示器固件、EDID、DDC 或系统显示配置 plist。

这是 [Apple 的应用/会话作用域语义](https://developer.apple.com/documentation/coregraphics/cgconfigureoption)，不是 Swift 的退出回调保证。崩溃或强制结束通常不会运行普通退出逻辑；不能用 `applicationWillTerminate` 冒充崩溃保障。连接本身包含私有 `CGSConfigureDisplayEnabled`，仍需逐设备验证作用域回收效果，不能承诺所有 macOS/硬件异常均能自动恢复。

**实际设备验收发现，仅 `.forAppOnly` 不足以恢复这台 Dell。** Lite 因此在新断开之前，启动同一签名可执行文件的无界面恢复子进程，并等待父进程退出监视器注册完成的确认。保护未就绪则拒绝断开。主界面异常终止时，子进程重新读取 Lite 记录、核对身份、恢复和验证当前目标，然后结束；失败时保留记录，最多尝试三轮。它不启动另一套界面，不安装 LaunchAgent、登录项或系统服务。

该保护覆盖主界面单独崩溃/强制结束；同时杀死两个进程、系统异常、硬件故障等仍不能保证。系统注销/重启结束登录会话是另一层配置回退边界。不存在“卸载事件必定触发恢复”的承诺。

旧记录若已确认编号被另一块屏幕复用，或离线记录早于本次开机，会持久标为“未接入 · 保留历史记录”。它不会再按旧编号启用其他屏幕，也不阻塞当前外屏操作和退出；记录不会被新屏覆盖。原屏幕重新在线并通过稳定身份匹配后，才可确认恢复并清除这条记录。

| 情形 | 行为与边界 |
| --- | --- |
| 正常退出 | 显式恢复并验证；失败留在 App |
| App 崩溃或被强制结束 | 恢复子进程尝试核对、恢复、验证并结束；不能只依赖应用作用域 |
| 覆盖安装 | 先恢复并退出旧实例，再替换对应 Lite bundle；恢复记录保存在 App 外，不被安装覆盖 |
| 删除 App 文件但进程还在运行 | 删除文件不等于结束进程；可能继续保持当前状态。先恢复、退出，再删除 |
| 旧版会话记录 | 覆盖安装本身不会证明已恢复；仍走原稳定目标重连和核验，不能把新作用域承诺追溯到旧断开 |
| 重启后旧编号可能复用 | UUID 不可读且记录早于本次开机时拒绝按旧编号盲目启用；重新接线并刷新 |
| 记录损坏或身份不唯一 | 暂停操作并保留原文件，不删除记录来制造成功 |

## 安装与卸载步骤

1. 打开当前 Lite，恢复它列出的外屏，确认目标出现且画面正常。
2. 选择退出；若仍提示当前待恢复，完成“恢复并退出”。未接入历史记录可保留，不阻止退出。失败时先处理恢复问题。
3. 退出后将新 `DisplayDJLite.app` 覆盖到原路径，或将它移到废纸篓卸载。不要把 Lite 覆盖到 `DisplayDJ.app`。
4. 无需手动删除 `~/Library/Application Support/DisplayDJLite/disconnected-displays.json`。保留它有助于旧版问题诊断；不要删除系统 WindowServer 配置文件。

开发机更新若旧实例已没有可识别外屏，无法完成第 1 步，必须记录失败、备份旧包并保留恢复文件，不能将复制成功记作恢复成功。

## 如果没有画面或不能恢复

1. 保留一块可用屏幕，打开 Lite，核对记录目标，尝试重新连接。错误和记录仍在时不要继续断开其他屏幕。
2. 核对外屏电源、连接和输入状态；重新连接线缆。打开 macOS 系统设置 → 显示器，按住 Option 显示“检测显示器”，执行检测。
3. 仍未识别时保存工作并重启 Mac，结束当前登录会话后再检查。Lite 不能替你自动注销或重启，也不建议删除系统配置文件。
4. 如仍失败，反馈 Lite/系统版本、Mac 架构、显示器型号、连接路径、具体错误和恢复结果。不要公开 UUID、序列号、token 或原始私人日志。

步骤 2/3 参考 [Apple 外接显示器排查](https://support.apple.com/en-us/102501)。这类失败不等于硬件已被永久损坏，也不能仅凭重启建议证明 Lite 在该设备上恢复可靠。

## 首发前的验收要求

已完成的单设备验收见 [实体设备恢复验收](LITE-DEVICE-VERIFICATION.md)。更广兼容性仍需在明确目标上记录：新断开 → 正常恢复退出、新断开 → 强制结束后系统回退、旧记录的恢复、覆盖安装前后记录保留、失败时不清记录，以及再次连接后的画面/拓扑。自动测试覆盖调用作用域与失败分支；真实屏幕上的 WindowServer 回收必须单列，不能被模拟测试替代。
