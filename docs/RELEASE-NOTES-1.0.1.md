# DisplayDJ 1.0.1

手动亮度调节现在优先于已有 Agent 会话；设置窗口和亮度条的交互也得到小幅改善。普通 CLI 仍可独立使用，本地服务按需启动。

## 主要变化

- **手动调节优先**：通过 App、CLI、HTTP 或亮度预设调节某块屏幕后，已有 Agent 会话跳过该屏后续阶段、结束和超时的亮度写入。其他屏幕及保活租约继续按配置处理；新会话从当前亮度建立恢复点。
- **恢复规则更明确**：旧会话不能从进程缓存恢复已被用户接管的亮度；重叠会话由最后一个仍持有控制权的会话恢复。直接 CLI 亮度修改保留显式撤销点，服务退出不会撤销手动背光值。
- **脚本能检查实际结果**：`agent begin/phase/end --json` 保留 `data.session` 并返回逐屏结果及跳过原因。损坏状态或运行中的旧版服务会拒绝亮度写入。
- **减少无效控制**：设置窗口隐藏内建屏、虚拟屏、镜像屏及无法确认稳定身份的屏幕的 DDC 音量／对比度区域。可探测外屏的“不支持”与“不可读取”分别显示，调节按钮保持禁用直到读取成功。
- **直接调节更跟手**：亮度条拖动取消弹簧延迟，填充和滑块同步；遵循系统“减少动态效果”，关闭相关过渡与数字滚动，并清理中断的拖动状态。
- **安装说明更清楚**：双语 README 优先介绍已安装的独立 CLI、PATH 配置和可选服务；下载入口使用最新 Release。

## 下载与升级

提供 Apple Silicon **arm64 ZIP、DMG 及 SHA-256**。App 采用 **ad-hoc 签名，未进行 Developer ID 签名或 Apple 公证**，macOS 可能阻止首次启动。可在 Finder 中按住 Control 点击 App 并选择“打开”，或前往“系统设置 → 隐私与安全性”允许打开。

升级前，用旧版本结束正在运行的 Agent 任务并停止本地服务，再替换 App；若曾将 CLI 复制到 PATH，也需重新复制包内的 `display-cli` 和兼容命令 `displaydj`。App、CLI 和运行中的服务必须使用 1.0.1，并共享同一状态目录。需要服务时，用新 CLI 执行 `display-cli serve --detach`；若仍提示旧服务，执行 `display-cli daemon restart`。

配置和亮度预设继续使用原目录。旧版恢复点仍可用于显式 `brightness restore`；缺少所有权信息的旧恢复点不会在服务退出时自动恢复，新 Agent 会要求先显式恢复或手动接管。不要在存在未完成任务或恢复点时切回旧版本。

全局快捷键需要辅助功能权限。替换 ad-hoc 签名 App 后可能需要重新授权；授权后若未立即生效，请退出并重新打开 DisplayDJ。

## 验证与边界

- 自动测试共 **651 项**通过；隔离 CLI／HTTP 烟雾测试不请求硬件写入。
- 本机内建屏实测覆盖正常恢复、跨 CLI 手动接管、后续阶段跳过、会话结束、服务退出保持手动值和显式撤销；结束时恢复原亮度并独立回读一致。
- 本轮没有外屏 DDC 实际写入及 GUI 人工交互验收，未扩大硬件兼容性承诺。最低部署目标为 macOS 13，本机实际验收环境为 Apple Silicon、macOS 27；Intel、最低系统、真实睡眠唤醒和干净用户升级尚未验证。
- 系统设置、显示器实体按键和其他应用的亮度修改不能触发本轮接管检测。Gamma 是软件调光，仍会随驻留进程退出释放，不等同于硬件背光。
