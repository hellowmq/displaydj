# DisplayDJ 1.0 发布验收清单

记录日期：2026-09-28。此页保留发布决策、已完成证据和明确接受的限制；物理设备结果以 [DEVICE-VALIDATION.md](DEVICE-VALIDATION.md) 的逐次记录为准。

## 1.0 承诺范围

目标是可靠的日常显示控制和独立 CLI，而非覆盖 BetterDisplay 全部显示技术。发布说明应逐项写明支持的平台、控制路径及已验证设备，避免把某台 HP 或 Dell 的结果推广到整个品牌。

人工双屏验收步骤、预期效果及本机日志命令见 [GUI-ACCEPTANCE-1.0.md](GUI-ACCEPTANCE-1.0.md)。

| 能力 | 1.0 决策 | 验收依据 |
| --- | --- | --- |
| 内建屏亮度、外屏 DDC 亮度 | 核心能力 | 分别实际写入、独立回读、恢复；DDC 失败必须给出可操作原因，不能伪报成功 |
| 每屏显式软件调光 | 核心能力 | 无 DDC 链路可选用；明确 Gamma 与硬件背光的差异，退出、重启、睡眠唤醒后恢复可靠 |
| 多屏目标与群组调节 | 1.0 日常体验目标 | 快捷键/滚轮目标可辨认且随焦点或用户选择变化；“全部屏幕”操作应展示逐屏结果并隔离单屏失败。持续跟随内建屏环境光变化可留后续版本 |
| DDC 对比度、音量 | 已有接口，按设备能力开放 | 仅对成功读写回读的显示器声称已验证；无扬声器/不支持的 VCP 明确失败 |
| 亮度预设、已有系统模式 | 核心能力 | 多屏保存/应用、失败回退；模式切换倒计时和不可见时自动恢复经过真实操作 |
| 断开/重连 | 高风险进阶能力 | 仅在有稳定身份、恢复路径和真实拓扑回读时开放；不承诺所有设备均支持 |
| 原生 Apple 亮度/媒体键、原生 OSD、连续硬件+软件混合曲线 | 有价值但可延期 | 当前固定快捷键及显式 Gamma 不能写成这些能力；若未完成，在 1.0 发布说明列为限制 |
| BetterDisplay 的虚拟屏、EDID 覆写、HDR/XDR 提升、PIP、LUT、输入源、CEC | 1.0 范围外 | 各自依赖硬件、兼容矩阵和独立恢复语义，不以竞品功能数量决定版本号 |

范围依据：[MonitorControl 官方功能表](https://github.com/MonitorControl/MonitorControl#major-features)列出多协议调光、同步、统一滑块、快捷键和 OSD；[BetterDisplay 官方免费/Pro 比较](https://github.com/waydabber/BetterDisplay/wiki/List-of-free-and-Pro-features)将基础同步、软件调光和组合调光列为免费能力，同时把部分高级显示功能列为 Pro。BetterDisplay 是独立应用，不是 MonitorControl 的付费版。以上仅用于范围决策，具体可用性仍取决于 Mac、系统、显示器和连接链路。

## 发布范围与剩余缺口

- 版本源与 smoke 断言统一为 `1.0.0`；`scripts/build-app.sh` 从 CLI 读取版本并写入 App 的 `CFBundleShortVersionString` 和 `CFBundleVersion`。
- `scripts/build-app.sh` 默认对 App 与两个 CLI 执行 ad-hoc 签名；设置 `DISPLAYDJ_SIGN_IDENTITY` 后可要求 Developer ID Application 签名、hardened runtime 和时间戳，并校验签名类型。1.0.0 明确选择 arm64、ad-hoc、未公证的 GitHub 直发范围，不声称 Gatekeeper 无提示安装。
- CI 目前只在 `macos-15` 运行构建、单测、CLI smoke 和 debug App 构建；没有 release 打包、包安装/升级、签名、公证与硬件测试。现有 README 声称最低 macOS 13，CI 尚未覆盖该最低版本。
- 自动启动服务通过 LaunchAgent 保存安装时解析的可执行文件绝对路径。升级 App 后，若旧服务仍在运行或它指向旧路径，客户端可能访问旧 API。升级验收必须读取 `daemon status` 的实际进程与路径，并验证重启后新旧版本一致。
- 最终 ZIP 与 DMG 必须从确定的 `v1.0.0` commit/tag 重新构建，不复用任何先前候选包。

## 发版前逐项核验

### 功能与硬件

- [x] HP 当前连接的 DDC 亮度、对比度：只读基线、小幅 Set VCP、独立回读和恢复通过；音量 VCP 0x62 明确不支持。连接线材与输入口、HP OSD 和肉眼变化仍待补证，不能推广到其他 HP 型号。
- [ ] 当前失败链路的无 DDC 路径：失败迅速、清楚且不会误写；用户主动选 Gamma 后可调节、关闭和恢复。
- [ ] 双屏：每屏目标、全部屏幕操作、预设跨屏及部分失败报告；拔插、休眠唤醒、服务退出时不丢失恢复状态。
- [x] 用户实际操作与授权验收：既有日志证实双屏同步写入及模式确认／超时恢复；用户确认快捷键排版，并完成辅助功能清理、当前 App 授权、重启和全局快捷键验证。Gamma 肉眼观感、错误文案及完整模式倒计时没有逐项视觉记录，作为发布限制保留。
- [ ] 正式模式切换的独立 15 秒守护进程已实现；keep、错误命令、管道关闭和超时协议测试通过。HP 的真实 WindowServer 上，CLI 的 keep、管道关闭、超时以及控制进程异常退出模拟均完成模式回读与恢复。仍需设置窗口的按钮、关闭窗口、可见倒计时和 App 本体异常退出验收；守护进程自身被强制结束时仍可能留下会话模式。
- [x] 对最终源码运行 `swift test`（626 项）、`python3 -B scripts/smoke.py`、release 构建和 `git diff --check`。

### 版本、安装与分发

- [x] 统一更新版本源、smoke 断言、README 和发布说明；最终包流程验证两个 CLI、Info.plist、ZIP／DMG 文件名和 Git tag 均为 `1.0.0`。
- [ ] 在干净用户环境验证首次启动；再从公开 `v0.3.0` 升级至候选 1.0，保留配置/预设，核查 LaunchAgent 绝对路径、旧服务停用和新接口可用，必要时可回滚到备份包。
- [x] 发布页明确标为 ad-hoc 签名、未公证构建，不声称 Developer ID、staple 或 Gatekeeper 无提示安装。
- [x] 只发布有构建证据的 arm64；`macOS 13+` 仍是部署目标，不写成最低版本实测结论。
- [x] 从确定的 `v1.0.0` 源码构建发布包，校验 SHA-256、CLI 版本、App bundle 版本、架构和签名；许可证与归属说明包含在仓库和 App 中。

离线包一致性检查：打包后运行 `python3 scripts/verify-package.py outputs/displaydj-1.0.0-macos-arm64.zip --expect-version 1.0.0`。脚本比较 ZIP 与本地 App 的每个文件、两个 CLI 和 Info.plist 版本、架构、SHA-256 sidecar 以及签名类型；正式检查拒绝 ad-hoc 签名。仅验证预览包时可加 `--allow-ad-hoc`。它不代替公证、Gatekeeper、首次启动与升级实测；运行前不要再重新构建本地 App，以免把不同批次构建误判为包内容不一致。

## 判定

1.0.0 按 arm64、ad-hoc、未公证的开源直发范围发布；不需要实现 BetterDisplay 的高级功能，也不等待付费 Developer ID。版本号本身不表示已取得 Apple 信任链、最低系统实测或广泛 DDC 兼容性。未完成项已在 README 和发布说明中限缩支持承诺。

以上不解除 GUI 观感、睡眠唤醒、干净用户升级、最低系统版本与正式签名公证等未完成项；这些已转为公开限制，不阻塞本次范围受限的 1.0.0 GitHub 直发。

## 2026-09-28 快捷键首次授权闭环

此前启用快捷键只安装监听并显示辅助功能说明，不调用系统授权提示；未授权时局部监听可在 App 窗口内工作，但用户必须自行找到系统列表并手动添加 App，全局路径实际上难以发现。现在仅在用户明确把快捷键从关切到开时调用系统辅助功能授权提示，等待授权期间保留“请求授权”和“打开系统设置”两个出口；从系统提示或设置返回 App 时自动重查权限，并在权限刚授予后重建全局监听。保存为开启的历史偏好在启动时不会主动弹出权限提示。
