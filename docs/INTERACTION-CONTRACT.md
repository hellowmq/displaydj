# Full / Lite 交互一致性契约

2026-10-25 更新。沿用 Full 已选第 1 稿和 Lite 已确认的恢复流程。一致性约束操作含义与反馈，不要求复制所有控件。

| 共同规则 | Full | Lite |
| --- | --- | --- |
| 品牌 | 原开口框与横杆；原生材质、cyan 强调 | 已通过的开口框与圆点；同一视觉家族，模板菜单栏图标 |
| 主要任务 | 逐屏亮度直接可调；连接属于次要动作 | 逐屏基础亮度直接可调，外屏连接仍直接可达 |
| 断开含义 | 从 Mac 桌面移除，窗口转到其他在线屏幕 | 相同；不声称关闭电源或切换输入源 |
| 断开确认 | 已实现逐屏文字菜单和独立原生确认；Return/Escape 安全取消 | 主按钮后显示独立原生确认，取消为安全默认；确认前无连接事务 |
| 目标身份 | 捕获稳定目标，提交前重新核验 | 相同；列表刷新不能把动作转移给另一个目标 |
| 操作反馈 | 请求/处理中/实际确认/失败分开 | 相同；目标行原位显示 pending，结果来自内核核验 |
| 恢复入口 | App 自己保存的记录，逐条重新连接 | 相同；保留行位置，未核验成功不清理记录 |
| 控件布局 | 列表中亮度和滚轮目标可见；配置进入偏好 | 名称、连接状态、逐屏亮度、连接动作；刷新、说明、退出直接可达 |
| 信息与颜色 | 文字/图标一起说明状态，语义色，长错误可换行 | 相同；正常断开为中性按钮，恢复为强调按钮，浅色 cyan 加深确保可读 |
| 键盘/动效 | 焦点、命名和键盘路径，减少动态效果后保留结果 | 相同；⌘R 刷新、⌘Q 退出，确认框 Return 取消，Escape 可取消 |
| 退出 | Full GUI 当前记录恢复并核验后退出，失败保留记录并取消；CLI 会话语义不变 | 有当前待恢复记录时恢复并退出/取消；失败留在 App；断开前确认恢复保护，历史记录单独标明 |

Lite 的外屏不拆成在线/离线两个会自动跳动的分区：外屏行在断开后保留原位置，离线时隐藏亮度并提供恢复。内建屏亮度单独列在前面。Full 的亮度区需要区分在线可控屏与恢复记录，可按已选稿分区；两个布局服务不同任务，不视为不一致。

本轮 Lite 改善：360pt 原生面板、13pt 屏幕名称、12pt 状态/错误、28pt 刷新点击区；连接与退出入口保持直接可见。完整错误信息可换行，屏幕全名可悬停读取。恢复记录只表示可尝试恢复，不把保存记录当作当前真实设备状态。

## 刷新与亮度反馈

两版共用原生 `arrow.clockwise`。按下立即局部反馈，每次受理只播放一次短促旋转；保持单色，不增加外圈，不用动画代替请求结果。持续超过 150ms 才显示静态“刷新中”，实际读取结束即恢复操作。macOS 13/14 或系统减少动态效果开启时不旋转，仍提供请求状态语义。

亮度数字使用等宽字体。拖动值、请求目标和已确认读数分开；旧请求的成功、失败和延迟清理不能覆盖新意图。亮度调节和后台读取不触发刷新动画。Lite 退出文字不随忙碌状态反复变灰，实际禁用与恢复检查仍保留。

模拟预览只改变内存数据，明确标注，不读取本机设备或写真实恢复记录。实际验收区分模拟、真实界面、物理设备和发布包，见 [2026-10-25 更新验证](RELEASE-REFRESH-2026-10-25.md)。连接异常与退出保护见 [恢复说明](LITE-RECOVERY.md)和 [Lite 实体设备验收](LITE-DEVICE-VERIFICATION.md)。
