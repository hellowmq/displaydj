# Full / Lite 交互一致性契约

2026-10-16。沿用 Full 已选第 1 稿和 Lite 已确认的恢复流程。一致性约束操作含义与反馈，不要求复制所有控件。

| 共同规则 | Full | Lite |
| --- | --- | --- |
| 品牌 | 原开口框与横杆；原生材质、cyan 强调 | 已通过的开口框与圆点；同一视觉家族，模板菜单栏图标 |
| 主要任务 | 逐屏亮度直接可调；连接属于次要动作 | 外屏连接为主动作；无需经过设置或更多菜单 |
| 断开含义 | 从 Mac 桌面移除，窗口转到其他在线屏幕 | 相同；不声称关闭电源或切换输入源 |
| 断开确认 | 已选稿要求文字菜单和独立原生确认，尚未实现 | 主按钮后显示独立原生确认，取消为安全默认；确认前无连接事务 |
| 目标身份 | 捕获稳定目标，提交前重新核验 | 相同；列表刷新不能把动作转移给另一个目标 |
| 操作反馈 | 请求/处理中/实际确认/失败分开 | 相同；目标行原位显示 pending，结果来自内核核验 |
| 恢复入口 | App 自己保存的记录，逐条重新连接 | 相同；保留行位置，未核验成功不清理记录 |
| 控件布局 | 列表中亮度和滚轮目标可见；配置进入偏好 | 名称、连接状态、单一主动作；刷新、说明、退出直接可达 |
| 信息与颜色 | 文字/图标一起说明状态，语义色，长错误可换行 | 相同；正常断开为中性按钮，恢复为强调按钮，浅色 cyan 加深确保可读 |
| 键盘/动效 | 焦点、命名和键盘路径，减少动态效果后保留结果 | 相同；⌘R 刷新、⌘Q 退出，确认框 Return 取消，Escape 可取消 |
| 退出 | Full 各控制路径遵循已有恢复语义，不因 Lite 改版改变 | 有当前待恢复记录时恢复并退出/取消；失败留在 App；断开前确认恢复保护，历史记录单独标明 |

Lite 不拆成在线/离线两个会自动跳动的分区：它的单任务行需要在断开后保留原位置。Full 的亮度区需要区分在线可控屏与恢复记录，可按已选稿分区；两个布局服务不同任务，不视为不一致。

本轮 Lite 改善：360pt 原生面板、13pt 屏幕名称、12pt 状态/错误、28pt 刷新点击区；连接与退出入口保持直接可见。完整错误信息可换行，屏幕全名可悬停读取。恢复记录只表示可尝试恢复，不把保存记录当作当前真实设备状态。

本轮未实现 Full 全面重设计。Full 第 1 稿的选中目标、亮度写入状态、设置分区和整理显示器按另行规划后续实施；其本地设计稿不包含在本次 Lite 发布提交中。连接回退和旧记录处理见 [恢复说明](LITE-RECOVERY.md)。

验收分开记录：模拟流程可验证取消、处理中与恢复入口；真实模式验证当前列表；真实断开/恢复必须有针对性授权与设备观察。模拟演示必须逐行、逐按钮明确标注，日常启动使用真实数据。

Lite 0.1.0：断开前必须确认恢复子进程的父进程退出监视器就绪；不能仅依赖 `forAppOnly`。已确认旧编号被复用的未接入历史记录保留、禁止盲目启用，不阻塞当前屏幕操作和退出。实体证据见 [LITE-DEVICE-VERIFICATION.md](LITE-DEVICE-VERIFICATION.md)。
